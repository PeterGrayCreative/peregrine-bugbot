# Deterministic post-canary decision gate

This section validates evidence only. It does not run a client, create provider
authority, alter the bridge or production routes, or authorize R5. The only
recommendations are `eligible-for-separate-batch-authorization` and `not-eligible`;
both retain false readiness, provider authorization and batch authorization.

The gate consumes independently pinned original registration, repository-only
mount manifest, R4 package, accepted runtime and bridge freezes. It validates the
complete unchanged 64-slot ledger, exact canary/prompt/route/source bindings, and
an externally authenticated observer receipt covering an exact raw-artifact
inventory. Pins must come from the trusted control plane, not be copied from a
candidate packet. A hash or model answer alone does not authenticate observation.

Required artifacts cover the bridge/start/invocation, raw CLI stream and output,
terminal/deadline, reader transcript and audit, full sealed gateway/forwarder
audits, observed client bytes/configuration/catalog/identity, model-to-tool-call
correlation, lifecycle/absence observations and before/after batch ledgers.
The separate observer and reviewer must be distinct from the model session.
The authenticated independent review must cover complete capability exposure,
leakage, unsupported identity claims and absence of a scored review.

Checks reject missing, malformed, failed, partial, unknown or mismatched evidence;
unknown/disallowed capability exposure/use; ambiguous terminal counters; reader
budget or source-byte drift; missing required listing/diff/search/literal-link or
registered no-link refusal; missing cancellation guard, client closure or complete
uncancelled cleanup; and any changed review slot. Existing wire-format parsers and
token accounting are reused. The first real registered mount has no native link;
that fact is derived from the authenticated inventory, not model narration.

Requested Sol/high must be observed where available. A known model mismatch or
self-reported positive backend identity fails. Exact backend identity may remain
null under the existing registration; a positive identity requires an independently
authenticated provider-metadata observation/reference. Normal completion proves
neither an elapsed timeout nor forced termination. The prior zero-provider
runtime evidence retains its separate classification.

`persistPredictionCanaryAssessment` writes a versioned, sealed create-only result;
`requirePredictionBatchAuthorization` always rejects, even an eligible assessment
with added approval flags. The observer/semantic review is an external trust input,
not proof generated by this validator. Its complete observation envelope is not
claimed to exist merely because the bridge recorded a terminal result.

Synthetic pass controls exercise both literal-link and no-link refusal paths.
Negative controls include independently re-pinned failures and internally
consistent re-sealed missing-operation/source-tamper records. Predecessor source
and failed validations remain in private `canary-assessment-v1/`. No actual
canary/observer receipt exists in this section: the real-data decision is
`not-eligible`, with all 64 review slots unchanged and unstarted.
